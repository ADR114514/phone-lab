# 实验标准作业流程（SOP）

> 本文件是三次实验的现场操作手册。数据可复现性依赖"同一台手机 + 同一 SOP + 同一分析脚本"，
> 因此每次实验的偏差都要写进 App 的 note 字段或 `session.log`。

---

## 课题02 · PowerTrace 功耗热测（4 工况 × 30 min）

### 0. 前置条件（一次性）
1. 手机电量 ≥ 90%，**不充电**（充电状态会污染电流读数）。
2. 关闭自动亮度，亮度固定 50%（记录实际值）；关闭自动旋转、AOD、蓝牙/NFC（按工况需要再开）。
3. 设置 → 应用 → 功耗热测仪：允许通知、**电池优化设为"不限制"**、允许"闹钟和提醒"（精确闹钟）、
   （可选）授予"使用情况访问"用于记录前台 App。
4. 保持同一 WiFi/移动网络与同一位置（避免信号强弱影响功耗），环境温度 20–28 °C，远离热源/阳光直射。
5. 记录初始电池温度（通常 28–32 °C）；若 >35 °C 先静置降温 15 min。

### 1. 批次流程（总约 2 小时 + 降温间隔）
| 顺序 | 工况 | 操作 | 备注 |
|---|---|---|---|
| A | IDLE 待机 | 锁屏放置，屏幕全黑 | 不要移动手机；通知可开 |
| B | VIDEO 短视频 | 固定同一 App 连续播放 30 min，音量 50%，亮度固定 | 记录 App 名称与分辨率/帧率 |
| C | NAVCAM 导航拍摄 | 打开导航 App 模拟导航 + 相机 4K/1080p 录像（可交替：15 min 导航 + 15 min 录像） | 记录是否开定位、是否开相机 |
| D | GAME 高帧率游戏 | 同一游戏、同一画质/帧率设置（如 90/120 fps 模式） | 记录游戏内帧率设置 |

- 每个工况 30 min，App 每 5 min 自动采样（0/5/10/15/20/25/30 min，共 6 点）。
- **工况之间静置 10 min 降温**，并检查起始电量差（不同工况起始电量应接近）。
- 每个工况开始前在 App 里填 note（App 名称、设置、环境）；结束立刻导出该工况 CSV，避免数据丢失。

### 2. 数据检查（当天完成）
- 每个 `session_*.csv` 是否 6 行；`campaign_*.csv` 是否 24 行；`charging` 是否全 0。
- 异常点（current_now_ua 为 0、温度跳变 >5 °C、采样迟到 >90 s）在 note 中标注原因。
- 用 `python analysis/power/analyze.py --data data/raw/power/<session> --out analysis/out/power` 跑通并看图。

### 3. 常见问题
| 现象 | 原因 | 处理 |
|---|---|---|
| 采样点缺失 | 系统杀后台/Doze | 确认电池优化豁免、精确闹钟权限；重跑该工况 |
| 电流恒为 0 | 机型不支持 CURRENT_NOW | 记录机型，分析改用 charge_counter 差分 |
| 温度为 0/异常 | 传感器不可用 | 记录机型；用 thermal status + 电池温度交叉判断 |
| 游戏工况 FPS 为空 | App 在后台无法测帧率 | 正常现象，在 note 写游戏内设置，分析用功耗代替 |
| 充电标记为 1 | 数据作废 | 拔线重跑 |

## 课题03 · SignalMap 无线盲区测绘（8 点位 × 3 次）

### 0. 点位设计（8 个不同遮挡特征）
走廊基准 / 90° 转角 / 电梯口 / 楼梯间 / 宿舍金属门 / 玻璃幕墙教室 / 设备机柜实验室 / 室外连廊。
每个点位记录：名称、类型、墙体材质、遮挡描述、到最近 AP 估计距离、楼层、现场照片（拍墙体与 AP 方向，避免拍到人脸）。

### 1. 单点流程（每次约 60–90 s，每点重复 3 次，间隔 ≥30 s）
1. 站在点位固定位置（地面贴标记保证 3 次位置一致），手机竖屏、与地面垂直，朝向保持一致。
2. 打开 App → 选择点位 → 拍照（首次）→ 开始测量。
3. App 自动完成：连接信息 → 邻道扫描 → 网关 RTT → 互联网 TCP RTT（20 次）→ HTTP TTFB/total（5 次）→ 写 CSV。
4. 3 次完成后移动到下一点位；**同一时段完成 8 个点**（避免网络负载随时间变化）。
5. 每个点位在表格中记录 AP 位置与遮挡物（如"吊顶内 AP，隔一道混凝土墙"）。

### 2. 环境控制
- 使用**同一运营商/校园网**、同一 AP 频段（2.4G 或 5G 分开测，别混）。
- 避开下课高峰与大量下载时段；记录测试时间。
- 关闭手机热点/VPN/代理；保持屏幕常亮。
- 定位开关必须打开（Android 12 起读 RSSI/扫描的前提），App 会检查。

### 3. 数据检查
- 24 行是否齐全（8 点 × 3 次）；每行 RSSI 是否在 -30 ～ -95 dBm 合理区间；
- 是否每个点都有照片；扫描明细是否非空（部分机型节流时可能为空，需记录）；
- 跑 `python analysis/wifi/analyze.py ...` 检查衰减表与盲区分级。

### 4. 常见问题
| 现象 | 原因 | 处理 |
|---|---|---|
| 扫描结果为空 | Android 12+ 扫描节流/权限不足 | 确认定位权限+定位开启；等待 30 s 重试；记录"scan 受限" |
| RSSI 为 -127 或 0 | 未连接 WiFi | 先连接目标 SSID 再测 |
| 延迟极高 | 网络拥塞/代理 | 关闭 VPN/代理，换时段重测 |
| 照片方向不对 | EXIF 旋转 | App 已按 EXIF 校正；仍异常则重拍 |

## 项目三 · VibroDiag 声振诊断（5 工况 × 15 组）

### 0. 设备与工况
- 设备：电风扇（3 档）、吹风机（2 档）、可选自行车（辐条/链条异响）。
- 5 工况：C1 低档正常、C2 高档正常、C3 扇叶轻微失衡（1 片贴 2 g 配重）、C4 进风口遮挡 1/2、C5 吹风机热风高速档。
- 每组 15 s，每工况 15 组，共 75 组；顺序建议打散（不要 15 组连续同工况，减少温漂/记忆效应）。

### 1. 单组流程
1. 手机固定：平放在设备正前方 30 cm 桌面（或三脚架），**麦克风朝向设备**，标记位置保证 75 组一致。
2. 环境：安静实验室（<40 dBA）；记录环境噪声；如做抗噪实验，用同一位置播放白噪声。
3. 选择工况 → 组号自动 → 3-2-1 倒计时 → 15 s 录制（不要说话/走动）。
4. 检查本组指标（RMS、峰值频率、加速度 RMS）是否在合理范围；异常（削波、脱落）立即重录。
5. 每 5 组休息 1 min（防设备升温），并轮换工况。

### 2. 盲测（录制视频用）
1. 数据集至少 5×15 组完成后，进入"盲测"：每工况 3 组、共 15 组，采集时不显示标签。
2. 一次盲测：录 → 预测（显示置信度）→ 揭示真实标签 → 下一组。
3. **录屏 2–4 分钟**：展示预测与揭示过程、最终 15 组准确率、混淆矩阵；视频保存为 `data/raw/vibro/blind_test_<date>.mp4` 或上传 B 站/网盘并附链接。

### 3. 抗噪实验
- 安静环境 + 播放白噪声/风扇噪声，分别达到 SNR ≈ 20/10/5/0/-5 dB（用声级计或 App 估算）。
- 每个 SNR 重复 5 组 × 5 工况；App 内"抗噪评估"生成曲线；报告给出准确率-SNR 曲线与失效点。

### 4. 异常数据判定
- 削波（peak 接近 0 dBFS）→ 降低音量/距离重录；
- 加速度饱和 → 手机远离设备；
- WAV 时长 < 目标 90% → 中断，重录；
- 同工况特征离群（如峰值频率偏离 >20%）→ 记录原因（电压波动/设备档位不同）后重录。

## 真机联调注意事项（OnePlus 12 / Android 16 实测）

- **权限**：部分厂商 ROM（ColorOS）会限制 `adb install -g` 与 `pm grant`，App 内的授权引导是唯一可靠路径；
  首次使用请逐项点"授权/去授权"，并在系统弹窗里选择"使用时允许"。
- **充电**：联调时手机通过 USB 连接电脑会进入充电状态，功耗/温升数据全部失效（CSV 的 `charging=1`）。
  必须拔线、仅用无线 adb 或提前导出数据；正式实验前确认 `charging=0`。
- **电流读数**：OnePlus 12 的 `BATTERY_PROPERTY_CURRENT_NOW` 在充电时接近 0（−124 µA）；
  放电状态才有意义，且不同厂商符号相反——分析脚本已取绝对值。
- **能量计数**：该机型不支持 `BATTERY_PROPERTY_ENERGY_COUNTER`，已按契约留空；
  请用 `charge_counter_uah` 差分与电量百分比交叉校验。
- **Wi-Fi**：Android 12+ 读取 RSSI 必须同时满足"定位权限 + 定位开关"；扫描结果可能被系统节流，
  App 会用缓存结果并在 note 标注"cache/受限"。
- **录音**：该机型支持 `MediaRecorder.AudioSource.UNPROCESSED`（无 AGC/降噪），优先使用；
  加速度计实际采样率 200.4 Hz，已写入 meta.json。
- **熄屏待机**：OnePlus/ColorOS 即使授予精确闹钟权限，也可能把 `setExactAndAllowWhileIdle` 按 App Standby 策略
  批量延后数小时（`dumpsys alarm` 可见 policy adjustment）。App 已改用 `setAlarmClock`（用户可见闹钟通道）
  并在 IDLE 工况持有守护 `PARTIAL_WAKE_LOCK`，保证 5 min 准点；代价是待机功耗含数十 mW CPU 驻留开销，
  报告中需说明，并建议做一次"开/关守护"对照实验量化偏差。
  实验前务必确认：电池优化豁免、通知权限、精确闹钟权限、屏幕锁定方式（建议关闭锁屏密码或用测试机）。
- **ColorOS/OnePlus 额外设置（实测必须）**：设置 → 电池 → 更多设置 → 关闭"睡眠待机优化"；
  应用信息 → 耗电管理 → 允许"后台活动/自启动"；否则深睡阶段可能冻结应用并延迟闹钟。
- **10 分钟试采门槛**：正式 30 min 待机批次前，先试采 10 min，确认前 3 个采样点都在 300 s ± 90 s 内；
  不满足则先排查系统设置，不要直接跑正式批次。
- 若迟到不可避免：保留数据（App 会标 `late_sample`），分析报告统计迟到/缺失并在报告中说明；不要手工改时间戳。

## 通用：数据归档与 Git 提交规范

1. 每次实验结束当天，把 App 导出的会话目录复制到 `data/raw/<app>/<session>/`。
2. 文本数据（CSV/JSON/MD/照片缩略）可直接提交；WAV/MP4/JPG 原图走 Git LFS 或 Release 附件。
3. 提交信息格式：`feat(powertrace): 完成 2026-11-18 批次 24 组采集`、`data(wifi): 补充 P03 电梯口复测`。
4. 每次数据提交附带一行 `data/raw/<app>/<session>/NOTES.md`：时间、地点、设备、环境、异常与处理。
